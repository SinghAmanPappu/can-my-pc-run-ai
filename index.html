12 tricks to fit more & run faster

Memory ≈ parameters × bits ÷ 8. A 7B model at 4-bit is about 4–5 GB. Always try 4-bit first.
Smaller context uses less RAM. Ollama: /set parameter num_ctx 4096 or llama-server -m model.gguf -c 4096.
Ollama: OLLAMA_FLASH_ATTENTION=1 and OLLAMA_KV_CACHE_TYPE=q8_0. llama.cpp: -fa --cache-type-k q8_0 --cache-type-v q8_0.
Mixture-of-Experts models such as gpt-oss:20b and qwen3:30b-a3b have huge total params but tiny active params — they fit where dense models won't.
Close your browser and other RAM-hungry apps before running a model. Disable startup apps you don't need.
Use -ngl 99 in Ollama to send layers to the GPU. Lower it if you run out of VRAM.
Two matching sticks (dual-channel) can nearly double CPU speed. On laptops, plug in the charger and use performance mode.
Set -t 6 (or your physical core count) instead of thread count. Hyper-threaded cores don't help inference much.
Increase page file (Windows) or swap/zram (Linux/macOS). Models will run, but slowly.
Google Colab and Kaggle Notebooks offer free GPUs within weekly limits.
Join two machines with exo or llama.cpp RPC mode to run a bigger model together.
Second RAM stick → SSD → GPU with more VRAM.
